# DaFeiYu Desktop Pet (Rust rewrite)

English | [简体中文](README.zh-CN.md)

<img src="docs/images/idle.png" width="180" align="right" alt="DaFeiYu">

A Windows desktop pet featuring the community fan character **DaFeiYu** (大肥鱼). The artwork and interaction model are based on dsh-pet; the runtime is a Rust rewrite that draws directly into a Win32 layered window. No Electron and no browser.

## Upstream projects

This is an independent rewrite, not a fork:

- **Primary source for assets and interaction semantics:** [PC2005-cloud/dsh-pet](https://github.com/PC2005-cloud/dsh-pet). Animation files come from its `dsh-pet/assets/webm/` directory. This project packs 100 clips; the six balance-event clips are intentionally excluded.
- **Additional interaction reference:** [1190fasheqi/dafeiyu-pet](https://github.com/1190fasheqi/dafeiyu-pet), a Python + PySide6 implementation. Only interaction semantics were consulted; none of its code or image assets are included here.

dsh-pet is a DSH plugin whose balance, whisper, and work-state animations depend on DSH events. This project runs the pet standalone: 100 animations, idle/sleep/drag/random actions, and a right-click animation menu. Whispers and work-state clips are still present, but are triggered by random playback and typing instead of DSH events.

## How the assets are processed

The upstream source is 106 VP9 webm clips. Playing them directly would require libvpx, slow startup, and a larger release. This project has its own packer and supports two output formats:

- **Production:** H.264 color in `.fishvid` plus a 1-bit alpha `.fishmask`; about 98MB for 100 clips.
- **Legacy:** `.fishanim` with premultiplied BGRA + zstd; about 654MB for 100 clips, kept for compatibility and comparison.

Both are packed from 100 clips composited on black. Edges and translucent effects need an alpha channel the source does not have, so `pack-anim --preview` also reads the preview GIFs the upstream ships (straight colour on 1-bit transparency) and solves `a = |C| / |F|` per pixel. That is why the numbers above are larger than the first release: brighter translucent pixels cost bitrate. The v0.1.1 packages predate this pass.

H.264 color is decoded by Windows Media Foundation. Alpha is not encoded into the video; it is stored separately at 1 bit per pixel, so transparent edges are not blurred by lossy compression. There is still no third-party decoder dependency.

The legacy format decodes one frame at a time at about 0.27ms/frame. The H.264 prototype is about 0.24ms/frame including the mask. Both are lightweight at 24fps.

## What is in this repository

The GitHub repository contains source code and documentation only. Animation assets, release builds, and upstream clones are intentionally not committed:

| Path | Why it is absent |
|---|---|
| `assets/` | Generated by `pack-anim` (~80MB), distributed through GitHub Releases |
| `dist/` | Generated by `package.ps1`; binaries live in Releases |
| `_upstream/` | Shallow clone of the upstream source, used for local packing |
| `target/` | Cargo build cache |
| `config.json` | Local runtime configuration; defaults live in code |

A fresh clone therefore cannot be launched by double-clicking an executable. Download a Release, or build the assets and binaries locally with the steps below.

## Run it (download a Release)

Rust is not required. Download a **v0.1.1 package**:

- [feiyu-h264-v0.1.1.zip](https://github.com/dsqrwym/DaFeiYu-Desktop-Pet/releases/download/v0.1.1/feiyu-h264-v0.1.1.zip) — 79.95MB, recommended
- [feiyu-fishanim-v0.1.1.zip](https://github.com/dsqrwym/DaFeiYu-Desktop-Pet/releases/download/v0.1.1/feiyu-fishanim-v0.1.1.zip) — 625.70MB, legacy
- [Release page](https://github.com/dsqrwym/DaFeiYu-Desktop-Pet/releases/tag/v0.1.1)

Both packages are attachments of the same `v0.1.1` Release. Prefer H.264 unless you specifically need lower runtime memory or the machine lacks the Media Foundation H.264 decoder.

v0.1.1 repacks the same 100 clips with a new matte pass. The source webm is composited on black, and the old keying gave every non-background pixel full opacity, which left a dark rim around the sprite and solid dark blobs where a translucent effect (bubbles, smoke, sparks) should be soft. Edge bands now get a fractional alpha solved from the inward neighbor, and the H.264 color plane stores straight instead of premultiplied color. See `docs/07` for the algorithm and its known limit.

After extracting the zip, enter `feiyu/`:

```
feiyu/
  feiyu.exe       double-click; no console window
  feiyu-cli.exe   command-line diagnostics (--selftest / --list / --showcase)
  config.json     user settings; restart after editing
  assets/anim/    100 .fishvid + 100 .fishmask (or .fishanim in the legacy package)
```

The assets sit next to the executable; nothing else needs to be installed. The two executables are about 0.8MB each (about 1.6MB total), and icons are embedded in their resources.

Why two executables: a Windows PE file can use only one subsystem. A console-subsystem build opens a terminal when double-clicked, while a GUI-subsystem build cannot provide synchronous command-line output. The GUI build is for everyday use; the console build is for diagnostics. Both run the same code.

```powershell
.\feiyu-cli.exe --selftest
.\feiyu-cli.exe --list
.\feiyu-cli.exe --config other.json
```

Verify the download:

```powershell
Get-FileHash .\feiyu-h264-v0.1.1.zip -Algorithm SHA256
```

### Which package should I choose?

| | H.264 (recommended) | `.fishanim` legacy |
|---|---:|---:|
| zip / extracted | **79.95MB / 80.8MB** | **625.70MB / 626.4MB** |
| Visible RSS | 77.2MB | **10.5MB** |
| Visible private memory | 65.2MB | **2.4MB** |
| Threads | 53 | **4** |
| Visible CPU | about 5%–7.5% of one core | **0.3%–2.8% of one core** |
| Decoder dependency | Windows Media Foundation H.264 | **No video decoder** |
| Random access | Media Foundation seek | **Direct diff-chain recomputation** |
| Image path | H.264 yuv420p + 1-bit alpha | **Premultiplied BGRA + zstd, full alpha** |
| Best for | Most users; smaller download | Memory-sensitive machines, older systems, lower runtime overhead |

Both packages contain 100 animations and pass `--selftest` at **94/94**. H.264 reduces the download by roughly 8×, but Media Foundation creates its own thread pool and internal buffers, so memory, thread count, and CPU are higher. This is not a leak: hidden-state CPU is 0%. If runtime resources matter more than download size, choose `.fishanim`.

## Configuration

`feiyu/config.json` is the file users edit; no recompilation is needed. If it is missing, built-in defaults are used. A malformed file produces a warning and falls back to defaults instead of preventing startup.

- `language`: `auto` (follow the system UI language), or `zh` / `en` / `es`. The menu's Language submenu writes this.
- `follow`, `click_walk`, `topmost`: the matching menu checkboxes; toggling them in the menu saves the value here.
- `action_gap`: delay between idle actions, in seconds, randomly chosen from a range
- `sleep_after`: idle time before sleeping, in seconds
- `typing`: typing-link toggle, trigger probability, heat threshold, decay, and cooldown
- `walk`: how far the pet walks in pixels
- `category_weights`: random-pool weight per category; `0` keeps a category in the menu but removes it from random playback

Category weights apply to the whole category and are then split across its clips. A larger number only changes the relative probability. Restart `feiyu.exe` after editing by hand. `--config other.json` can point at a temporary file.

The menu writes back only what it can change (`language`, `follow`, `click_walk`, `topmost`, `typing.enabled`); any other field you edited by hand is left alone. The right-click menu is available in Chinese, English, and Spanish; clip names come from a built-in translation table, so the shipped asset packages do not need to be re-packed.

## Build from source

Requirements: Windows 10/11, Rust stable, Visual Studio 2022 C++ build tools (linker), and ffmpeg when packing assets.

```powershell
git clone https://github.com/dsqrwym/DaFeiYu-Desktop-Pet.git
cd DaFeiYu-Desktop-Pet
powershell -ExecutionPolicy Bypass -File tools/fetch-assets.ps1

# Production format: H.264 + 1-bit mask
cargo run -p pack-anim --release -- --src _upstream/dsh-pet/dsh-pet/assets/webm --out assets/h264 --codec h264 --crf 20 --preview _upstream/dsh-pet/dsh-pet/assets/preview

# Legacy format (optional, for compatibility/comparison)
cargo run -p pack-anim --release -- --src _upstream/dsh-pet/dsh-pet/assets/webm --out assets/anim --preview _upstream/dsh-pet/dsh-pet/assets/preview

cargo run -p feiyu-app --release
```

`fetch-assets.ps1` shallow-clones the upstream into `_upstream/dsh-pet`; that directory and `assets/` are not committed.

`cargo run` prefers `assets/h264` (H.264) and falls back to `assets/anim` (legacy `.fishanim`) when the H.264 directory is absent. Use `--dir` to select a directory explicitly. `cargo run` launches the console build by default because `default-run = "feiyu-cli"`; logs and exit codes stay in the terminal.

Package a release build:

```powershell
powershell -ExecutionPolicy Bypass -File tools/package.ps1 -AnimDir assets/h264
```

## Compared with the original

| | Original [dsh-pet](https://github.com/PC2005-cloud/dsh-pet) | This version |
|---|---|---|
| Runtime | DSH plugin: browser overlay or Electron transparent window | Native Win32 layered window |
| Dependencies | DSH + Node; about 104MB Electron download for desktop mode | No third-party runtime; H.264 uses Windows Media Foundation |
| Disk | webm 51.8MB + about 104MB Electron download | **80.8MB** (H.264 + mask + two executables); legacy `.fishanim` package 626.4MB |
| Memory | Not measured on this machine | H.264: 77.2MB RSS / 65.2MB private / 53 threads; legacy: 10.5MB / 2.4MB / 4 threads |
| CPU | Not measured | H.264: about 5%–7.5% of one core (0.4%–0.6% of a 12-core machine); legacy: 0.3%–2.8% of one core |
| Frame cost | — | H.264: about 0.24ms (decode + mask); legacy `.fishanim`: 0.265ms |

Disk usage is now in the same range as the original (81MB vs 51.8MB of webm plus about 104MB of Electron). The 626MB legacy package is kept for comparison; its advantage is that it does not depend on Media Foundation and has direct frame access.

### H.264 package measurements (kept separate from the legacy numbers)

Measured with the packaged `feiyu.exe --run 45`, a 5-second warm-up, and a 30-second sampling window (v0.1.1 package):

- Visible: RSS **77.2MB**, private **65.2MB**, **53 threads**, CPU **4.9%–7.5% of one core** (0.4%–0.6% of a 12-core machine) across three runs.
- Hidden: RSS **39.6MB**, private **21.9MB**, 19 threads, CPU **0%**.
- Full `--showcase`: **100/100 clips**, exit code 0, **16.7 minutes** wall-clock.

The H.264 package uses about 7× the memory and many more threads than the legacy package. That is the cost of the Media Foundation decoder and its thread pool. CPU drops to 0.4%–0.6% of the whole 12-core machine, but the single-core reading is genuinely higher. The legacy figures (10.5MB / 4 threads / 0.3%–2.8%) are a separate measurement and must not be averaged with these numbers.

CPU varies because DWM can skip composition when the window is occluded. Historical 60-second samples for the legacy package were 1.4%–1.7% of one core.

## Features

- Idle, sleep (three-stage choreography), click responses (five randomized clips), drag/fling physics, and self-directed walking
- 97 clips available from the right-click menu; 89 clips in the random pool
- Mouse-follow turning, click-to-walk, and typing-triggered work animations, each switchable from the menu
- Tray mode freezes the icon on the frame that was visible when the pet was hidden

## Verification

```powershell
# Extracted release package
.\feiyu-cli.exe --selftest # 94 checks
.\feiyu-cli.exe --showcase # 100/100, about 16.7 minutes

# Source build
cargo test --workspace --release          # 115 tests
.\target\release\feiyu-cli.exe --selftest # 94 checks
```

`selftest` opens a real window, submits real bitmaps, and captures the screen; it covers transparency, hit testing, menu structure, the tray, baseline alignment, sleep spans, and typing integration. `cargo test` covers pure logic only.

Full showcase:

```powershell
.\feiyu-cli.exe --showcase
```

It plays all 100 clips once, takes about 16.7 minutes, and completed 100/100 with exit code 0 during the recorded run.
