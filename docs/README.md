而是把一个真实项目从需求、架构、代码到踩坑全部摊开，给不会 Rust 的人看。

## “逐行讲”是怎么做的

一个 8000 行的项目，把每一行都写成“这行是左花括号”没有意义。这里的做法是：

1. **语法只讲一次**：同一个语法点（比如 `?`、`match`、借用）在 02 里用项目代码讲透，
   后面不再重复；
2. **每个文件都讲**：04~07 覆盖 `crates/` 与 `tools/` 下的每一个 `.rs` 文件；
3. **每个函数都讲**：函数的输入、输出、关键分支、为什么这么写；
4. **关键行逐行讲**：算法核心（差分链、命中测试、菜单三件套、睡眠接缝）逐行拆开；
5. **测试也是代码**：测试里的断言说明了“作者认为什么必须成立”，04~06 会一并讲。

读完之后，你再看任何一行代码，都能在 02 里找到它用的语法，在 03 里找到它在架构里的位置。

## 配套材料

- 项目笔记（不入库，本地有）：`_notes/PROGRESS.md`（现在到哪了）、`_notes/LESSONS.md`（踩过的坑）。
- 实测数据：README 的“实测数字”表，每一项都写明了怎么测。
- 每个模块顶部都有 `//!` 文档注释，解释“为什么要有这个文件”，比代码本身更值得读。
