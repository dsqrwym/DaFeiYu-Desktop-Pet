# 01 先跑起来

> [English](en/01-getting-started.md) | 简体中文

这一章只做一件事：让你在本机把项目跑起来，并且知道每条命令在干什么。
**没跑起来之前不要读代码**——读代码时你会不断怀疑“这是我改坏的吗”。

## 1. 检查环境

打开 PowerShell，逐条执行：

```powershell
rustc -V          # 期望：rustc 1.8x / 1.9x
cargo -V          # 期望：cargo 1.8x / 1.9x
rustup show       # 期望：active toolchain = stable-x86_64-pc-windows-msvc
ffmpeg -version   # 只有打包素材时需要
```

缺少 Rust：装 [rustup](https://rustup.rs/)，它会提示安装 **Visual Studio C++ 生成工具**
（链接器 `link.exe` 在里面）。这不是可选项——Rust 在 Windows 上默认用 MSVC 工具链。

## 2. 认识目录

```
D:\...\FeiYu
├── Cargo.toml            工作区清单：一个仓库里有 4 个 crate
├── rust-toolchain.toml   固定用 stable + msvc target
├── crates/
│   ├── feiyu-core/       纯逻辑：不碰 Windows，能单测（含 config.rs、mask.rs）
│   ├── feiyu-platform/   唯一允许 unsafe / windows::* 的层（含 Media Foundation）
│   └── feiyu-app/        主程序：pet/、frame_source.rs、cli.rs、main.rs + bin/feiyu-cli.rs、selftest.rs
├── tools/
│   ├── pack-anim/        webm → .fishanim / .fishvid + .fishmask
│   └── fetch-assets.ps1  拉上游素材
├── assets/h264/          生产格式产物（不入库，本机生成）
├── assets/anim/          旧格式产物（可选，不入库）
├── dist/                 发布包（不入库，只在 GitHub Releases 分发）
├── docs/                 你正在读的文档
├── _upstream/            上游浅克隆（不入库）
└── _notes/               开发笔记（不入库）
```

**为什么分 4 个 crate**：编译期就能挡住“纯逻辑层偷偷用了 Windows API”。
`feiyu-core` 的 `Cargo.toml` 里只有 zstd/serde/thiserror，没有 `windows`，
所以它必须在任何平台上都能编译——这就是“分层”从口头约定变成机器检查。

## 3. 两种跑起来的方式

### A. 直接下载 Release（推荐，不需要 Rust）

打开 [v0.1.0 Release](https://github.com/dsqrwym/DaFeiYu-Desktop-Pet/releases/tag/v0.1.0)，下载
`feiyu-h264-v0.1.0.zip`，解压后双击 `feiyu/feiyu.exe`。旧 `.fishanim` 包也在同一 Release，
体积更大但运行内存更低；区别见根目录 README。

### B. 从源码构建

```powershell
# ① 拉素材（浅克隆到 _upstream/，不入库）
powershell -ExecutionPolicy Bypass -File tools/fetch-assets.ps1

# ② 打包生产格式（约 2~3 分钟，产出 assets/h264/）
cargo run -p pack-anim --release -- --src _upstream/dsh-pet/dsh-pet/assets/webm --out assets/h264 --codec h264 --crf 20

# ③ 运行（默认优先 assets/h264）
cargo run -p feiyu-app --release
```

旧格式仍可打包：把 `--out assets/h264 --codec h264 --crf 20` 换成 `--out assets/anim`。
第一次 `cargo build` 会编译全部依赖，几分钟是正常的；之后改一行代码重新构建只要几秒。

> `cargo run -p feiyu-app` 里的 `-p` 是“package”，告诉 cargo 运行哪个 crate 里的 bin。
> 本项目的二进制名是 **feiyu**（见 `crates/feiyu-app/Cargo.toml` 的 `[[bin]]`），
> 不是 `feiyu-app`。

## 4. 跑测试与自检

```powershell
cargo test --workspace --release        # 113 条单元测试
.\target\release\feiyu-cli.exe --selftest   # 94 项真机自检，逐项打勾
```

两者的分工：

| | 单元测试 | 自检 |
|---|---|---|
| 跑在哪 | `cargo test`，无窗口 | 真的开一个分层窗口、真的提交位图、真的抓屏 |
| 测什么 | 纯函数：容器编解码、状态机转移、物理、睡眠接缝 | Win32 这条链：透明、命中测试、菜单、托盘、脚底对齐 |
| 能不能在 CI 跑 | 能 | 不能（需要桌面会话和素材） |

⚠️ **`--selftest` 跑的是 `target\release\feiyu-cli.exe`**，而 `cargo test` 不会重建它。
改了代码先 `cargo build --release`，否则你测的是旧二进制。

**为什么有两个 exe**：Windows 的 PE 只能有一个子系统。`feiyu.exe` 是 GUI 子系统，
双击不弹终端；但它从 PowerShell 启动时，PowerShell 不会等待，输出会跑到提示符后面。
所以诊断命令统一用 `feiyu-cli.exe`（console 子系统，输出和退出码都是同步的）。
两者跑的是同一份 `cli_main`，行为完全一致。

## 5. 第一次改代码

先改一个**不用重新编译**的参数，建立“改 → 重启 → 看效果”的循环：

1. 把 `config.example.json` 复制成 `config.json`（放在仓库根或 exe 旁边）；
2. 找到 `action_gap`，把 `[8, 15]` 改成 `[2, 4]`；
3. `cargo run -p feiyu-app --release`，观察它是不是两三秒就换一个随机动作；
4. 改回去。

`action_gap` 控制“两次随机动作之间隔多久”（秒，区间内随机）。为什么不直接设成 1 秒？
因为一直扭来扭去的桌宠会显得焦躁——**参数背后是产品判断，不是技术限制**。

这个参数以前写死在 `pet.rs` 里，改一次要重新编译；现在由 `feiyu-core/src/config.rs`
读 JSON，缺失或写错都回退默认值。代码只负责“默认值是什么、范围怎么收敛”，
产品参数交给配置文件。

## 6. 常见错误对照表

| 报错/现象 | 原因 | 解决 |
|---|---|---|
| `link.exe not found` / `LINK : fatal error` | 没装 MSVC C++ 生成工具 | 重跑 rustup，选“修改”，勾选 MSVC 与 Windows SDK |
| `读不了素材清单 ...\assets\h264\manifest.json` | 还没打包素材，或目录指错 | 执行第 3 步的 ②；旧格式用 `assets/anim` |
| `打不开动画 ...` | 素材目录不完整 / 打包中断 | 重跑 pack-anim |
| pack-anim 报 `无法启动 ffmpeg` | ffmpeg 不在 PATH | 把 ffmpeg 的 bin 目录加进 PATH，或用 `--ffmpeg` 指定 |
| 运行后看不到鱼 | 窗口在屏幕底部中央、可能被任务栏挡住；或被“总在最前”关掉 | 右键托盘/桌面找它；看日志 |
| 改完代码效果没变 | 测的是旧 exe | `cargo build --release` 再跑 |
| 自检失败但单测全过 | 自检测的是真实 Win32 行为 | 逐条看失败项，通常是环境（DPI/托盘/素材） |

## 7. 调试开关（只用环境变量，不改代码）

项目里每个“看不见的行为”都留了一个取证开关，设了就打印日志：

```powershell
$env:FEIYU_EVENT_TRACE=1     # 每个窗口事件 + 菜单返回值与耗时
$env:FEIYU_SEAM_TRACE=1      # 每次动画回绕的接缝读数
$env:FEIYU_DRAG_TRACE=1      # 按下 → 进入拖拽姿态的毫秒数
$env:FEIYU_WAKE_TRACE=1      # 睡着时每次“自然醒”掷骰的点数
$env:FEIYU_TYPING_TRACE=1    # 打字联动每次尝试
$env:FEIYU_TYPING_EAGER=1    # 打字联动必触发、不过冷却（仅验证用）
```

这些开关是**排查工具**，不是功能。用完记得 `Remove-Item Env:FEIYU_EVENT_TRACE`。
