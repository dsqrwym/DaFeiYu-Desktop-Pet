# 03 架构与“一次点击的旅程”

## 1. 四层，依赖只能单向

```
feiyu-app ──→ feiyu-platform ──→ feiyu-core
  (组装)         (Win32)          (纯逻辑)
                                   ↑
                  tools/pack-anim ─┘
```

- `feiyu-core`：**不碰 Windows**。动画容器、`.fishmask` 1-bit 掩码、状态机、物理、睡眠编排、用户参数都在这里，
  因此可以在任何机器上 `cargo test`。
- `feiyu-platform`：唯一允许 `unsafe` 与 `windows::*` 的层。它把 Win32 封装成
  “窗口 / 菜单 / 托盘 / 输入 / H.264 解码”几个小接口。
- `feiyu-app`：把两者组装起来。`pet/frame_source.rs` 是“第几帧从哪来”的抽象
  （`.fishanim` 或 `.fishvid + .fishmask`）；`pet/` 其余文件是“大脑 + 渲染循环”，按职责分成数据表
  （`clips.rs`）、菜单（`menu.rs`）、走路（`walk.rs`）、打字（`typing.rs`）、
  睡眠（`sleep.rs`）、跟随（`follow.rs`）和像素工具（`pixels.rs`）；`cli.rs` 是命令行与模式，
  `main.rs` / `bin/feiyu-cli.rs` 是两个入口（GUI 与 console），`selftest.rs` 是验收。
- `pack-anim`：把 webm 变成 `.fishanim` 或 `.fishvid + .fishmask`，只依赖 `feiyu-core` 的格式定义。

**为什么不让 app 直接调 Win32**：一旦允许，`pet/` 里会混进 `HWND`、
`UpdateLayeredWindow` 之类的细节，逻辑就没法测了。现在的 `pet/` 能读，
正是因为它只调 `self.win.draw(...)`、`feiyu_platform::cursor_pos()` 这种小接口。

## 2. 只有一个 UI 线程

Windows 的窗口消息只在创建窗口的线程上处理。所以整个程序是：

```
主线程：CreateWindowEx → pump(GetMessageW → DispatchMessageW → wndproc)
                                   ↓ 事件入队
                         pump 每取一条消息后清空队列 → on_event(ev) → Pet::tick/draw
```

定时器（`SetTimer`，8ms）只是**往队列里塞一条 `Event::Tick`**，不直接调业务代码。
这样所有业务逻辑都在同一个线程上顺序执行，不需要锁（除了 `WndState` 那个给
`WM_NCHITTEST` 用的像素缓冲）。

`wndproc` 里绝不画图、不做耗时操作：它只把事件 `push` 进 `VecDeque`，
然后立刻返回。否则会卡住消息循环，菜单、拖拽都会顿。

## 3. 三套坐标，必须分清

这是本项目最容易写错的地方，也是“换动画不跳位”的关键。

| 坐标系 | 原点 | 用途 |
|---|---|---|
| 屏幕像素 | 屏幕左上角 | 窗口位置、鼠标位置 |
| 原始画布 | 544×306 的左上角 | `manifest.json` 里的 `origin` / `baseline` |
| 帧内像素 | 裁切后帧的左上角 | 实际提交给 `UpdateLayeredWindow` 的位图 |

打包时会把每段动画裁到“不透明像素的并集包围盒”，所以每段帧尺寸不同。
为了换动画时角色不跳位，清单里记了两个量：

- `origin`：裁切帧左上角在 544×306 画布中的位置；
- `baseline`：**帧内**脚底线（角色脚底在帧里的 y）。

于是窗口位置统一由锚点算出：

```rust
// 锚点 = (角色中心 x, 脚底 y)
let x = anchor_x - canvas_width / 2 + origin_x;
let y = feet_y - baseline;
```

这就是 `pet/mod.rs` 的 `window_pos()`。所有“摆窗口”的地方必须走它——
同一个公式散落三份时，改动漏掉一处就会变成“纵向错 46 像素”的 bug。

## 4. 一次点击的完整旅程

假设用户用左键点了鱼一下。

### 4.1 消息到达

1. `WM_LBUTTONDOWN` 进入 `wndproc`；
2. `wndproc` 记录 `SetCapture` 和按下时的鼠标偏移（准备拖拽），
   然后 `push(Event::MouseDown { x, y })`；
3. `pump` 取到消息，分发后清空队列，回调 `on_event(MouseDown)`。

### 4.2 业务层

`Pet::on_event` 只做三件事：记录 `grab_origin`、把 `dragging` 置 false、
预热 `drag` 动画文件（`ensure_loaded("drag")`）。

### 4.3 松手

1. `WM_LBUTTONUP` → `Event::MouseUp`；
2. `Pet::on_button_up`：如果 `dragging == false`，说明这是“点击”，走 `clicked()`；
3. `clicked()`：
   - 如果正在睡，走 `wake_up()`（从当前帧演到最后一帧）；
   - 否则 `stimulate(Stimulus::Click)` → `Brain` 把心情切到 `Happy`（或连点三次 `Pout`）；
   - `stimulate` 里按心情选素材：`Happy` 从 5 段点击回应里随机抽一段；
   - `play(id)` 换动画、`after_switch` 处理进场；
   - `action_playing = true`，表示“演完一圈要收回待机”。

### 4.4 下一拍

1. 定时器 → `Event::Tick` → `Pet::tick()`；
2. `tick` 先算 `dt = now - last`，推进状态机（睡眠、打字联动、物理）；
3. 用 `acc += dt * fps` 累积时间，够一帧就 `step_frames(1)`；
4. `step_frames` → `advance_frame` 推进帧号（到段尾要处理回绕/淡入）；
5. `draw_frame` 解出当前帧像素 → 需要镜像就镜像 → 需要接缝淡入就混合 → `win.draw()`；
6. `win.draw()` 把预乘 BGRA 位图交给 `UpdateLayeredWindow`，DWM 合成到屏幕。

### 4.5 演完

`step_frames` 发现帧号回绕且 `action_playing`：
把 `action_playing` 置 false，`resume_idle_at()` 回到 idle，重新安排下一次入睡/随机动作。

**一句话总结**：Win32 只负责“把事件塞进队列”，`pet/` 负责“根据事件和时间决定播哪一帧”，
`core` 负责“这些决定背后的纯逻辑”。

## 5. 一次拖拽

1. 按下：记录抓取偏移，预热 drag；
2. 移动超过 2 像素：`DragStart` → 播 `drag`，`loop_span=35..110`（跳过“还站在地上”的前 35 帧）；
3. 拖动中：`WM_MOUSEMOVE` 直接 `SetWindowPos` 跟手，同时记录最近 120ms 的采样；
4. 松手：用首尾采样估速度（`fling_velocity`），交给 `Motion` 做抛物线与反弹；
5. 落地且速度足够小 → `rest`，再保持 drag 姿态 0.1 秒才回待机。

为什么松手不立刻切回 idle？因为鱼还在空中。`landed_at` 只在 `Motion::step` 返回 `rest`
时置位，所以“还在飞”不会被误判成“已经落地”。

## 6. 一次入睡

`SleepCycle` 把 10 秒的 `sleep` 素材拆成三段：

| 阶段 | 帧区间 | 行为 |
|---|---|---|
| `Falling` | 0~156 | 站着 → 闭眼蜷下 → Z 气泡 1→2→3 |
| `Asleep` | 104~156 | 只在“2~3 个气泡”那一截循环 |
| `Waking` | 当前帧~240 | 点醒时从当前帧往后演，Z 自己飘散 |

`advance_frame` 在段尾调用 `cycle.on_segment_end()`：入睡→睡着返回 true，
睡着段返回 false（继续原地循环）。醒来段不回绕，演完由 `step_frames` 交回待机。

为什么这么复杂？因为素材是**一整段 10 秒闭环**：当普通循环播会“睡十秒自己醒”，
不循环又只能睡两秒。这段编排是逐帧量出来的，细节在 04 的 `sleep.rs`。

## 7. 状态都在哪

| 状态 | 存在哪 | 为什么 |
|---|---|---|
| 心情（待机/睡/开心/生气/被拖） | `Brain.mood` | 纯逻辑，可单测 |
| 当前动画 id / 帧号 / 时间余量 | `Pet` | 和窗口绑定 |
| 帧来源（fishanim / h264 + mask） | `pet::FrameSource` | 播放器只认“第几帧” |
| 产品参数（入睡/动作间隔、打字、走路、权重） | `core::Config` | 启动读一次，运行时只读 |
| 走路剩余距离/方向/速度 | `Pet.walk` | 每帧推进 |
| 物理速度 | `Pet.motion` | 松手后才有 |
| 睡眠阶段 | `SleepCycle` | 纯逻辑，可单测 |
| 打字热度/冷却 | `Pet` | 依赖 `Instant` |
| 窗口像素 alpha | `platform::WndState` | `WM_NCHITTEST` 要读 |

一个原则：**能放进 `core` 的纯逻辑就放进去**。`Brain`、`Motion`、`Pool`、`SleepCycle`
都在 `core`，所以它们有单测；`Pet` 只负责“把纯逻辑的结论翻译成窗口操作”。
