# 09 练习与下一步

这一章的练习按难度排序，每个都给出**验收标准**。做完一个再做下一个，
不要一次改三个地方——出了问题你会分不清是谁的错。

---

## 练习 1（热身）：改一个配置并观察

**目标**：建立“改配置 → 重启 → 观察”的循环。

1. 把 `config.example.json` 复制成 `config.json`（仓库根或 exe 旁边）；
2. 把 `action_gap` 从 `[8, 15]` 改成 `[2, 4]`；
3. `cargo run -p feiyu-app --release`，用 `--verbose` 看切换日志；
4. 改回去。

**验收**：日志里随机动作的间隔明显变短；改回去后恢复。你能说出这个参数
为什么不能设成 0（提示：`brain.elapsed()` 同时用于判睡）。

---

## 练习 2：让一段现有动画进入另一个分类

**目标**：理解 `CATEGORIES` 是随机池和菜单的唯一数据源。

1. 把 `"turn"` 从「转向」分类挪到「小动作」分类；
2. `cargo test -p feiyu-app --release`（分类权重合计变了，测试会提醒你）；
3. `feiyu-cli.exe --list` 看它出现在哪个分类；
4. `feiyu-cli.exe --showcase 小动作` 看它是否被演示；
5. 改回去。

**验收**：`--list` 的分类变化；单测里 `category_weights_match_upstream`
如果合计不再是 100 会失败——这就是“数据表被测试钉住”的意义。

---

## 练习 3：端到端新增一段动画

**目标**：走完 `NAME_MAP → CATEGORIES → CLIPS → 打包 → 验证` 的完整链路。

假设你有一段 `新动作.webm`（24fps、10 秒、黑底）：

1. `tools/pack-anim/src/main.rs` 的 `NAME_MAP` 加 `("新动作", "new_action")`；
2. `pet/clips.rs` 的 `CATEGORIES` 里放进「小动作」；
3. 如果它有前摇（开头几帧站着），在 `CLIPS` 里加：

   ```rust
   ClipSpec {
       id: "new_action",
       desc: "一句话说明应该看到什么",
       span: Some((20, 200)),
       walk: None,
       on_enter: OnEnter::Plain,
   },
   ```

4. 重新打包 `cargo run -p pack-anim --release -- --src ... --out assets/anim`；
5. `feiyu-cli.exe --list` 确认出现；
6. `feiyu-cli.exe --showcase new_action` 肉眼看；
7. `feiyu-cli.exe --selftest`。

**验收**：`--list` 里有它；`--showcase` 能完整播一圈；自检的“清单 N 段 → 菜单 N-3 段”
数量关系仍然成立；如果它有地面道具，脚底线抽查不报错。

## 练习 4：给自检加一条

**目标**：学会把“必须成立的事”写成自动检查。

例子：验证「菜单里每一段的命令 id 都是连续的」。

1. 在 `selftest.rs` 的 `check_interaction` 里，用 `pet.menu_clip_ids()` 拿到 97 个 id；
2. 逐个 `pet.dispatch_menu_clip(i)`，断言 `pet.current() == ids[i]`（注意每段演完要
   `advance_frames(245)` 回待机，否则会卡在动作里）；
3. 打印 `✓ 97 段菜单序号全部对位`。

**验收**：故意把 `menu_clips()` 的过滤条件改错一项，这条检查必须失败；
改回来后通过。

---

## 练习 5：给纯逻辑加一条单测

**目标**：学会测“性质”而不是“当前值”。

例子：`Pool::pick` 在权重为 0 时不能选中。

1. 在 `pool.rs` 的 `tests` 里加一条：

   ```rust
   #[test]
   fn zero_weight_never_picked() {
       let pool = Pool::new([("a", 0u32), ("b", 5)]);
       let mut rng = Rng::new(1);
       for _ in 0..1000 {
           assert_eq!(pool.pick(&mut rng), Some("b"));
       }
   }
   ```

2. `cargo test -p feiyu-core --release`。

**验收**：测试通过；把 `add` 里的 `weight == 0` 判断删掉，测试必须失败。

## 练习 6：缩短点击回应的时长（需要先量化）

**目标**：一次完整的“量化 → 改 → 验证”。

现状：点击回应是整段 10 秒。用户可能觉得太长。

1. `feiyu-cli.exe --showcase click_happy` 看整段，记下“反应最精彩”的帧区间；
2. 在 `pet/clips.rs` 的 `CLIPS` 里给 5 段点击回应各加一个 `span`（跳过开头/结尾）；
3. 注意 `clicked()` 里的 `action_playing` 逻辑：有 `span` 时到段尾会回绕，
   不能把整段演完，需要确认 `step_frames` 的回绕判定仍然成立；
4. 跑 `--selftest`，再真机点几下。

**验收**：点一下的反应明显变短；`--selftest` 全绿；连续点 3 下仍会生气。

> 这道题没有标准答案：`span` 取多少要靠你看素材。这就是“素材决定代码”。

## 练习 7：加一个菜单开关（照着打字联动抄）

**目标**：学会“一个开关”要改哪些地方。

以“随机动作开关”为例：

1. `pet/menu.rs` 加 `CMD_RANDOM: CommandId = 8;`，`pet/mod.rs` 加字段 `random_actions: bool`；
2. `build_menu` 加 `.check(CMD_RANDOM, "随机动作", self.random_actions)`；
3. `dispatch` 加一条切换分支，`Action` 加 `Random(bool)`；
4. `tick` 里抽随机动作的条件加上 `&& self.random_actions`；
5. `selftest` 的菜单项数加一；
6. `cli.rs` 的 `menu_event` 加打印分支。

**验收**：菜单多一项；关掉后 60 秒内不出现随机动作；自检全绿。

## 练习 8（进阶）：给配置加一个新字段

**目标**：走一遍“默认值 → 解析 → 校验 → 使用 → 示例文件 → 测试”的完整链路。

现在 `follow.rs` 里的 `LOOK_COOLDOWN = 4.0` 还是写死的。把它变成 `config.json` 的
`look_cooldown_sec`：

1. `core/config.rs` 的 `Config` 加 `look_cooldown_sec: f32`，`Default` 给 4.0；
2. `RawConfig` 加 `Option<f32>`，在 `from_json` 里用 `number(...)` 解析并夹到
   `0.5~60.0`（冷却太小会一直扭头）；
3. `follow.rs` 把常量换成 `self.cfg.look_cooldown_sec`；
4. `config.example.json` 补上这个字段；
5. `config.rs` 的测试加一条：缺字段时是 4.0，负数被夹回下限。

**验收**：改配置后转头冷却真的变了；删掉字段仍能启动；`cargo test` 与
`--selftest` 全绿。

> 这是一次小重构，按项目约定**先写清楚字段、范围、失败回退再动手**。
> 注意：不要让 `Config` 直接依赖 `Pet`——配置只存值，怎么用是 app 的事。

## 练习 9（进阶）：继续拆 `pet/mod.rs`

**目标**：体验“按职责拆”而不是“按行数拆”。

`mod.rs` 还剩约 1600 行，混了播放器、事件处理、托盘、几何。可以按这三块继续拆：

- `playback.rs`：`play` / `tick` / `advance_frame` / `Dissolve` / 动画缓存；
- `events.rs`：`on_event` / `on_moved` / `on_button_up` / `clicked` / 拖拽物理；
- `tray.rs`（app 层）：`hide` / `unhide` / `enable_tray` / 定格图标。

**验收**：`cargo test` 与 `--selftest` 全绿；行为无变化；`mod.rs` 降到 800 行以内。

> 重构的规矩：**先出方案，确认后再动代码**；一次只拆一个方向；
> 拆完必须用自检证明行为没变。

## 已知缺口（截至本轮）

这些是“知道但还没做”的，不是忘了：

| 缺口 | 现状 | 建议 |
|---|---|---|
| 菜单真机观感 | 结构已由 Win32 自检验证，宽度/位置需人眼 | `feiyu-cli.exe --menu` |
| 全量演示 | `--showcase` 100 段约 17 分钟 | 按分类跑，逐类打勾 |
| 点击回应时长 | 整段 10 秒 | 练习 6 |
| H.264 边缘 | CRF20 在 4 倍放大下仍有块状；alpha 已用 1-bit 掩码做到精确 | 接受 71MB 档；或转 VP9 alpha |
| H.264 兼容 | `VideoReader` 目前只走 RGB32，NV12 fallback 未实现 | 遇到无 RGB32 转换的系统再补 |
| `pet/mod.rs` 体量 | 约 1600 行 | 练习 9 |

素材已经分成两档：生产 H.264 包 **71.1MB**，旧 `.fishanim` 包 583MB 保留兼容/对照。

托盘点击那个老问题需要 v4 协议，按当前决定**不处理**，也不在练习里安排。

## 最后一句

这份文档不是“读完就会 Rust”，而是“读完知道一个 Rust 项目长什么样、怎么做事”。
真正的进步来自：**改一个小东西 → 跑测试 → 看日志/截图 → 记录为什么**。
这个项目里每一个奇怪的常量背后，都有一次真实的返工；你踩过一次，就真的记住了。
